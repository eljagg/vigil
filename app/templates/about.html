About Vigil

Version {{ version }} · Backup integrity check

Vigil is a backup integrity check tool. It helps operations teams verify that scheduled backup files exist, are correctly named, and have plausible sizes — week after week, with a clear audit trail of who scanned what and when.

What Vigil does

  • Records that a folder was scanned, by whom, on which workstation, and at what time.
  • Compares each file's size against the previous scan of the same folder, surfacing files that grew, shrunk, or appeared for the first time.
  • Flags files whose sizes changed by more than a threshold (default 20%) as anomalies worth investigating.
  • Tracks a weekly rotation so the right operator is on duty for backup verification.
  • Supports admin-defined "expected paths" with cadences (daily / weekly / fortnightly) and surfaces overdue paths automatically.
  • Sends weekly reminder emails to the on-duty operator listing paths still due for scanning.

How Vigil works (architecture)

Vigil is built around a deliberate split between the browser and the server, chosen specifically to keep file contents off the network. When an operator clicks Browse on the New Scan page, the browser's File System Access API hands Vigil a permission token for the chosen folder. The browser then walks the folder (including all subfolders) reading only three pieces of information per file: filename, size in bytes, and last-modified timestamp. This list — a "manifest" — is the only thing posted to the Vigil server.

The server stores the manifest in a Postgres database and computes the diff against the previous scan of the same folder. No file content ever crosses the network. No file content is ever stored.

For details on exactly what Vigil reads, what it does not read, and how to verify these claims independently, see the Data handling page.

Technical stack

  • Backend: Python 3.12 / Flask 3 / SQLAlchemy 2 / PostgreSQL 16
  • Frontend: vanilla JavaScript using the File System Access API (Chrome, Edge, Brave, Opera, Chromium)
  • Authentication: argon2id password hashing, optional TOTP 2FA, optional LDAP/AD integration
  • Hosting: containerized, deployed via Railway with Postgres plugin

Browser support

Running scans requires the File System Access API, which is supported by Chromium-based browsers (Chrome, Edge, Brave, Opera, Vivaldi) on Windows, macOS, and Linux. Firefox and Safari can view existing scans but cannot run new ones — Mozilla and Apple have not yet shipped this API. Mobile browsers are not supported for scanning.
